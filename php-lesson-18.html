Ազնիվ նշում՝ սկզբից

Laravel-ին տրված է չորս դաս։ Դա ծանոթություն է, ոչ տիրապետում։

Այս չորս դասից հետո կկարողանաս կարդալ Laravel-ի կոդը, հասկանալ ինչու է այն այդպես գրված և կառուցել պարզ նախագիծ։ Աշխատանքային մակարդակի համար պետք կլինի ևս 2–3 ամիս ինքնուրույն աշխատանք։

Բայց մի առավելություն ունես, որ շատերը չունեն․ գիտես, թե ինչ է անում ֆրեյմվորքը ներսում։ Երբ ինչ-որ բան կոտրվի, չես մնա փակուղում։

1. Ժամանակ։ Այն, ինչ գրեցիր չորս դասում, Laravel-ը տալիս է մեկ հրամանով։

2. Փորձարկված կոդ։ Քո Router-ը ստուգվել է քո ձեռքով մեկ շաբաթ։ Laravel-ինը՝ հազարավոր նախագծերում տասը տարի։ Նրա CSRF-ում հայտնաբերված խոցելիությունը շտկվում է բոլորի համար միանգամից։

3. Ընդհանուր լեզու։ Laravel գիտեցող ցանկացած ծրագրավորող կբացի քո նախագիծը և անմիջապես կհասկանա, որտեղ ինչ է։ Քո սեփական ֆրեյմվորքը հասկանում ես միայն դու։ Դա ամենամեծ պատճառն է, որ ընկերությունները ֆրեյմվորք են ընտրում։

02Տեղադրում

Տարբերակների մասին — ստուգիր ընթացիկը

Այս դասը գրված է Laravel 13-ի համար (թողարկվել է 2026-ի մարտին)։ Այն պահանջում է PHP 8.3 կամ ավելի նոր — 8.2-ը այլևս չի աջակցվում։

Laravel-ը նոր հիմնական տարբերակ թողարկում է տարին մեկ անգամ։ Եթե կարդում ես սա ավելի ուշ, ստուգիր laravel.com/docs-ում ընթացիկ տարբերակի պահանջները։ Հիմնական գաղափարները՝ routing, Blade, Eloquent, չեն փոխվում տարիներով։

1. ստուգում

php -v

# Եթե ցածր է՝ Laragon → Menu → PHP → Version → ընտրիր 8.3 կամ նորը

# Composer-ը՝ Դաս 14-ից
composer --version
2. նոր նախագիծ — ՏեխնոՄարկետի կողքին

cd C:\laragon\www

composer create-project laravel/laravel technomarket-laravel

# Laragon → Reload
# → http://technomarket-laravel.test
Ինչո՞ւ նոր նախագիծ, ոչ փոխարինում

Հին ՏեխնոՄարկետը մնում է կողքին։ Ամեն դասում կբացես երկու պատուհան՝ քո Router.php-ը և Laravel-ի routes/web.php-ը, և կհամեմատես։

Սա «հայելու» մեթոդն է, որ ընտրեցինք Laravel-ի չորս դասի համար։ Երկու նախագիծը օգտագործում են նույն MySQL բազան, ուստի տվյալները փոխանցել պետք չէ։

3. .env — միացում քո բազային

# Փոխում ենք MySQL-ի
DB_CONNECTION=mysql
DB_HOST=127.0.0.1

DB_DATABASE=technomarket

# Laravel 11+-ը լռելյայն սեսիաներն ու քեշը պահում է ԲԱԶԱՅՈՒՄ ⚠️
# Մեր հին բազայում sessions և cache աղյուսակներ չկան —
# առայժմ ֆայլեր։ Դաս 20-ում նոր բազայով կվերադառնանք database-ին
SESSION_DRIVER=file
CACHE_STORE=file
SQLite-ի թակարդը

Laravel 11-ից սկսած նոր նախագիծը լռելյայն օգտագործում է SQLite՝ ֆայլ database/database.sqlite։ Դա հարմար է արագ սկսելու համար, բայց քո ապրանքները այնտեղ չեն։

Եթե մոռանաս փոխել DB_CONNECTION-ը, էջը կբացվի, բայց ցուցակը դատարկ կլինի — առանց ոչ մի սխալի։ Լուռ սխալներից ամենաշփոթեցնողն է։

Երկրորդ թակարդը նույն պատճառից. նոր նախագծում SESSION_DRIVER=database է։ MySQL-ի փոխելուց հետո ամեն էջ կտա «Table 'technomarket.sessions' doesn't exist», որովհետև այդ աղյուսակը ստեղծվել էր SQLite-ում, ոչ մեր բազայում։ Ուստի առայժմ file։

.env-ը փոխելուց հետո՝ php artisan config:clear, եթե երբևէ կեշավորել ես կոնֆիգը։

4. ստուգիր, որ Laravel-ը տեսնում է բազան
php artisan db:show

# categories, products, orders, order_items, users
Եթե .test հասցեն չի բացվում

Laragon-ը սովորաբար ինքն է ճանաչում Laravel նախագծի public/ թղթապանակը։ Եթե բացվում է թղթապանակների ցուցակ կամ 403 — ստուգիր DocumentRoot-ը, ինչպես Դաս 15-ում։

Կամ օգտագործիր Laravel-ի ներկառուցված սերվերը՝ php artisan serve → http://127.0.0.1:8000։ Այն հարմար է արագ փորձարկման համար, բայց Դաս 1-ում ասացինք, որ իրական Apache-ին ավելի մոտ է Laragon-ը։

APP_KEY — մի՛ կիսվիր

composer create-project-ը ինքն է գեներացնում APP_KEY-ը։ Laravel-ը դրանով ծածկագրում է սեսիաները և cookie-ները։

Ով գիտի այդ բանալին, կարող է կեղծել ցանկացած օգտագործողի սեսիա։ Այն .env-ում է, իսկ .env-ը արդեն .gitignore-ում է՝ ինչպես Դաս 14-ում։ Նաև՝ մի՛ դիր այն AI-ի չաթում (Դաս 4)։

05Routing՝ հայելին

քո routes.php — Դաս 15–16
$router->get('/',               [$productController, 'index']);
$router->get('/product/{slug}', [$productController, 'show']);

// /admin-ը պաշտպանված էր public/index.php-ում
$router->get('/admin', [$adminController, 'index']);
Laravel-ի routes/web.php
<?php

use App\Http\Controllers\ProductController;
use App\Http\Controllers\AdminController;
use Illuminate\Support\Facades\Route;

Route::get('/',               [ProductController::class, 'index'])->name('home');
Route::get('/product/{slug}', [ProductController::class, 'show'])->name('product.show');

Route::middleware('auth')->group(function () {
    Route::get('/admin', [AdminController::class, 'index'])->name('admin.index');
});
Համեմատիր տող առ տող

[ProductController::class, 'index']-ը համարյա նույնն է, ինչ քո [$productController, 'index']-ը։ Տարբերությունը մեկն է․ դու տալիս էիր պատրաստի օբյեկտ, իսկ Laravel-ին տալիս ես դասի անունը, և այն ինքն է ստեղծում օբյեկտը միայն այն ժամանակ, երբ ուղին համընկնում է (Դաս 19)։

{slug}-ը նույն շարահյուսությունն է, ինչ քո Router-ում։ Ներսում Laravel-ը նույնպես այն վերածում է ռեգուլյար արտահայտության։ Route::middleware('auth')-ը քո str_starts_with($path, '/admin') ստուգման կազմակերպված տարբերակն է։

Միակ իսկական նորությունը՝ ->name()-ն է։

Անվանված ուղիներ — Դաս 15-ի «երեսուն տեղի» խնդիրը

route() — url()-ի հասուն տարբերակը
// Դաս 15-ում՝
url('/product/' . $p->slug)

// Laravel-ում՝ ըստ ԱՆՎԱՆ, ոչ ըստ ուղու ⭐
route('product.show', $p->slug)

// Query պարամետրերով
route('home', ['sort' => 'price_desc'])
// → /?sort=price_desc
Ինչո՞ւ սա ավելի լավ է, քան մեր url()-ը

Դաս 15-ում ասացինք․ «վաղը որոշում ես, որ հասցեն պիտի լինի /products/{slug}։ Հիմա պիտի գտնես բոլոր երեսուն տեղը»։ Մեր url()-ը օգնեց միայն մասամբ՝ '/product/' տողը դեռ կրկնվում էր ամեն տեղ։

route('product.show', ...)-ը ուղին չի պարունակում ընդհանրապես։ Փոխում ես routes/web.php-ում մեկ տող, և բոլոր հղումները թարմանում են ինքնաբերաբար։

Եվ բոնուս՝ եթե տառասխալ անես անվան մեջ, Laravel-ը կգցի սխալ անմիջապես, ոչ թե կստեղծի կոտրված հղում։ Նույն գաղափարը, ինչ Դաս 12-ի $product->prise-ը․ սխալը բարձրաձայն է, ոչ լուռ։

06Request և Response

app/Http/Controllers/ProductController.php
<?php

namespace App\Http\Controllers;

use Illuminate\Http\Request;
use Illuminate\Support\Facades\DB;

class ProductController extends Controller
{
    private const SORTS = [
        'price_asc'  => ['price', 'asc'],
        'price_desc' => ['price', 'desc'],
        'name'       => ['name', 'asc'],
        'newest'     => ['created_at', 'desc'],
    ];

    public function index(Request $request)
    {
        // Դաս 10-ի սպիտակ ցուցակը — Laravel-ը քեզ չի ազատում դրանից ⭐
        $key = $request->query('sort', 'price_asc');
        [$column, $direction] = self::SORTS[$key] ?? self::SORTS['price_asc'];

        $products = DB::table('products')
            ->where('is_active', 1)
            ->orderBy($column, $direction)
            ->paginate(12);          // ⭐ էջավորում՝ մեկ բառով

        return view('products.index', [
            'products' => $products,
            'sort'     => $key,
        ]);
    }

    public function show(string $slug)
    {
        $product = DB::table('products')
            ->where('slug', $slug)
            ->where('is_active', 1)
            ->first();

        abort_if($product === null, 404, 'Ապրանքը չի գտնվել');

        return view('products.show', ['product' => $product]);
    }
}

Դաս 15-ում որոշեցինք 404-ը գցել NotFoundException-ով, ոչ թե echo + exit-ով, որովհետև կոնտրոլերը չպետք է որոշի, թե ինչպես ցույց տալ սխալը։

Laravel-ի abort()-ը գցում է բացառություն՝ HttpException։ Ճիշտ այն որոշումը, որ կայացրինք Դաս 15-ում։ Հիմա գիտես ոչ միայն ինչ է անում այն, այլ նաև ինչու է այդպես նախագծված։

Query builder-ը պաշտպանում է արժեքները, ոչ սյունակների անունները

->where('slug', $slug)-ը ներսում օգտագործում է prepared statement — Դաս 10-ի պաշտպանությունը ինքնաբերաբար է։

Բայց ->orderBy($request->query('sort'))-ը վտանգավոր է։ Սյունակի անունը չի պարամետրացվում (Դաս 10, բաժին 05), և Laravel-ը չի կարող իմանալ, որ sort-ը պիտի լինի միայն չորս արժեքից մեկը։

Դրա համար վերևի կոդում SORTS-ը մնացել է։ Ֆրեյմվորքը չի ազատում քեզ մտածելուց։

Իսկ ի՞նչ չի պաշտպանում

1. {!! $x !!} — Blade-ի «առանց փախցնելու» ձևը։ Դաս 5-ում մեր $content-ի պես է․ միայն արդեն պատրաստ HTML-ի համար։ Օգտագործողի տվյալը այստեղ՝ XSS։

2. href="{{ $url }}" — {{ }}-ը չի փրկում javascript:-ից։ Դաս 5-ի safeUrl()-ը Laravel-ում էլ է պետք։

3. DB::statement("... $x") — հում SQL տողերի միացումով։ Prepared statement-ը աշխատում է միայն այն դեպքում, երբ արժեքը փոխանցում ես առանձին։

4. orderBy($request->sort) — սյունակների անունները (բաժին 06)։

5. Mass assignment — Դաս 17-ի զգուշացումը։ Laravel-ը ունի $fillable, բայց եթե գրես $guarded = [], պաշտպանությունը անջատվում է։ Դաս 20-ում։

6. Բիզնես-կանոնները — qty <= 99, «ապրանքը առկա՞ է»։ Ֆրեյմվորքը չգիտի քո կանոնները։
