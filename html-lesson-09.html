display և նորմալ հոսք

Ինչո՞ւ են div-երը շարվում իրար տակ, իսկ span-երը՝ կողք կողքի։ Այսօր հասկանում ենք էջի բնական հոսքը — վերջին քայլը մինչև մեր դասավորության համակարգը։

Նախապայման՝ Դաս 06–08 Բլոկ 1 · CSS հիմունքներ Կամուրջ Դաս 10-ին

00Ի՞նչ ենք սովորելու այսօր

  • Ի՞նչ է նորմալ հոսքը
  • block — ամբողջ տողով
  • inline — տեքստի հոսքում
  • inline-block — երկուսի միջև
  • display: none vs visibility: hidden
  • overflow
  • Ինչո՞ւ inline-block-ը բավարար չէ դասավորության համար

01Նորմալ հոսք

Բրաուզերն ունի լռելյայն ձև՝ էլեմենտները դասավորելու։ Այն կոչվում է նորմալ հոսք, և այն աշխատում է, նույնիսկ եթե ոչ մի CSS չես գրել։

Սա լռելյայն է, ոչ վերջնական

display հատկությամբ կարող ես ցանկացած էլեմենտի վարքագիծը փոխել։ li { display: inline } — և ցուցակը դառնում է հորիզոնական մենյու։

02block

վարքագիծը
.box {
    display: block;

    /* Ամեն ինչ աշխատում է */
    width: 300px;
    height: 200px;
    margin: 20px;
    padding: 20px;
}
  • Սկսվում է նոր տողից
  • Զբաղեցնում է ամբողջ հասանելի լայնությունը, եթե width չկա
  • Ընդունում է width, height, բոլոր margin-ները և padding-ները
  • Կարելի է կենտրոնացնել margin: 0 auto-ով
«Ամբողջ լայնությունը» ինչ է նշանակում

Ոչ թե էկրանի, այլ ծնողի լայնությունը։ div-ը 300px լայնությամբ ծնողի ներսում կլինի 300px, ոչ 1920։

03inline

սահմանափակումները
.tag {
    display: inline;

    width: 200px;        /* ❌ անտեսվում է */
    height: 100px;       /* ❌ անտեսվում է */
    margin-top: 20px;    /* ❌ անտեսվում է */
    margin-bottom: 20px; /* ❌ անտեսվում է */

    margin-left: 20px;   /* ✅ աշխատում է */
    padding: 20px;       /* ⚠ աշխատում է, բայց... */
}
Ուղղահայաց padding-ի տարօրինակությունը

inline էլեմենտի վրա ուղղահայաց padding-ը նկարվում է (ֆոնը մեծանում է), բայց տեղ չի զբաղեցնում։ Արդյունքում այն մտնում է հարևան տողերի վրա և ծածկում դրանք։

Հենց դրա համար են inline էլեմենտները անհարմար ցանկացած դասավորության համար։

  • Չի սկսվում նոր տողից
  • Զբաղեցնում է միայն իր բովանդակության չափը
  • Անտեսում է width, height, ուղղահայաց margin
  • Հոսում է որպես տեքստ, տողադարձվում է
Հիմա պարզ է

Հիշո՞ւմ ես Դաս 6-ի global.css-ից՝ a { display: inline-block }։

Հղումը լռելյայն inline է։ Առանց այդ տողի կոճակ-հղումին չէիր կարողանա տալ padding: 10px 20px և չափեր։ Հիմա գիտես՝ ինչու է այն այնտեղ։

04inline-block

Հիբրիդ․ դրսից inline է (կողք կողքի), ներսից՝ block (ընդունում է չափեր)։

լավագույնը երկուսից
.btn {
    display: inline-block;

    width: 150px;       /* ✅ */
    height: 44px;        /* ✅ */
    margin: 10px;        /* ✅ բոլոր ուղղություններով */
    padding: 12px 24px;  /* ✅ ճիշտ է աշխատում */
}

05Ինչո՞ւ inline-block-ը բավարար չէ

Թվում է՝ գտանք լուծումը դասավորության համար։ Բլոկները կողք կողքի են և ընդունում են չափեր։ Բայց կան երեք լուրջ խնդիր։

Խնդիր 1 — առեղծվածային բացակը

երեք սյուն 33.33%-ով չեն տեղավորվում
<!-- HTML -->
<div class="col">1</div>
<div class="col">2</div>
<div class="col">3</div>
.col {
    display: inline-block;
    width: 33.33%;
}
/* Երրորդ սյունը ընկնում է ներքև */
Պատճառը

inline-block էլեմենտները հոսում են որպես բառեր։ Իսկ HTML-ում դրանց միջև կա տողադարձ, որը բրաուզերի համար բացատ է — մոտ 4px։

33.33% + 4px + 33.33% + 4px + 33.33% > 100%։ Երրորդն ընկնում է։

«լուծումները», որոնք տգեղ են
<!-- 1. Գրել առանց տողադարձի -->
<div class="col">1</div><div class="col">2</div><div class="col">3</div>

<!-- 2. Կոմենտարով «կուլ տալ» բացատը -->
<div class="col">1</div<!--
--><div class="col">2</div>

/* 3. Ծնողին font-size: 0 */
.row { font-size: 0; }
.col { font-size: 16px; }   /* վերականգնել ամեն երեխայում */

Բոլորն էլ աշխատում են, և բոլորն էլ վատն են։ Առաջինը՝ կոդն անընթեռնելի է դառնում։ Երկրորդը՝ տարօրինակ է։ Երրորդը՝ պիտի հիշես վերականգնել տառաչափը ամենուր։

Խնդիր 2 — ուղղահայաց հավասարեցում

տարբեր բարձրության քարտեր
/* Երկու քարտ՝ մեկը 200px, մյուսը 300px բարձրությամբ
   Ի՞նչ է լինում — դրանք հավասարեցվում են ըստ ՎԵՐՋԻՆ ՏՈՂԻ,
   ոչ ըստ վերին եզրի                                        */

.col { vertical-align: top; }   /* պիտի գրես ձեռքով */

Խնդիր 3 — հավասար բարձրություն

Երեք քարտ տարբեր տեքստերով։ Ուզում ես, որ դրանք լինեն հավասար բարձրության, և կոճակները՝ նույն մակարդակին։ inline-block-ով դա հնարավոր չէ առանց ֆիքսված բարձրության։

Ահա թե ինչու է եկել Flexbox-ը

2010-ականներին դասավորությունը կառուցում էին float-ով և inline-block-ով՝ բոլոր այս հնարքներով։

Flexbox-ը լուծում է բոլոր երեք խնդիրը միանգամից. բացատներ չկան, gap-ը կանխատեսելի է, երեխաները լռելյայն հավասար բարձրության են։

11-րդ դասին կսովորենք այն։ Իսկ մինչ այդ՝ 10-րդ դասին կկառուցենք կմախքը, որի վրա այն կնստի։

06Թաքցնելու ձևերը

երեք տարբեր բան
/* 1. Ամբողջովին անհետանում է, տեղ չի զբաղեցնում */
.hidden { display: none; }

/* 2. Անտեսանելի է, բայց տեղը մնում է */
.invisible { visibility: hidden; }

/* 3. Թափանցիկ է, տեղը մնում է, դեռ սեղմելի է */
.transparent { opacity: 0; }
Տեղ զբաղեցնո՞ւմ էՍեղմելի՞ էԷկրանընթերցիչը կարդո՞ւմ է
display: noneՈչՈչՈչ
visibility: hiddenԱյոՈչՈչ
opacity: 0ԱյոԱյոԱյո
.visually-hiddenՈչ—Այո
opacity: 0-ի թակարդը

Թափանցիկ կոճակը դեռ սեղմվում է։ Օգտագործողը սեղմում է դատարկ տեղում և ինչ-որ բան է կատարվում։ Եթե ուզում ես իսկապես անջատել՝ ավելացրու նաև pointer-events: none։

Հիշիր .visually-hidden-ը

Դաս 6-ի global.css-ից։ Այն օգտագործվում է, երբ տեքստը պետք է միայն էկրանընթերցիչին՝ օրինակ, բաժնի վերնագիրը, որը դիզայնում չկա։ display: none-ը այդ դեպքում սխալ ընտրություն է — այն թաքցնում է բոլորից։

07overflow

Ի՞նչ անել, երբ բովանդակությունը չի տեղավորվում տուփի մեջ։

չորս արժեք
.box { overflow: visible; }  /* լռելյայն — դուրս է գալիս */
.box { overflow: hidden;  }  /* կտրվում է */
.box { overflow: scroll;  }  /* միշտ սքրոլ */
.box { overflow: auto;    }  /* սքրոլ միայն երբ պետք է ✅ */

/* Առանձին առանցքներով */
.table-wrap {
    overflow-x: auto;
    overflow-y: hidden;
}

Երկու սովորական կիրառություն

գործնականում
/* 1. Կլորացված քարտ նկարով */
.card {
    border-radius: 12px;
    overflow: hidden;    /* նկարի անկյունները կկտրվեն */
}

/* 2. Լայն աղյուսակ հեռախոսում */
.table-wrap {
    overflow-x: auto;    /* աղյուսակը սքրոլվում է, էջը՝ ոչ */
}
Հորիզոնական սքրոլը էջի վրա — սխալ

Եթե ամբողջ էջը հորիզոնական սքրոլվում է հեռախոսում, ինչ-որ բան դուրս է եկել։ Մի՛ ծածկիր այն overflow-x: hidden-ով body-ի վրա — գտիր մեղավոր էլեմենտը։

DevTools → հեռախոսի ռեժիմ → նեղացրու էկրանը և տես, թե ինչն է դուրս գալիս։

Երկար բառերի կտրումը

Հայերենում բառերը երկար են և կարող են դուրս գալ նեղ բլոկից։ Լուծում՝
overflow-wrap: break-word; — բառը կտողադարձվի, եթե չի տեղավորվում։

08Խաղահրապարակ

Փորձիր ավելացնել font-size: 0 .row-ib-ին
Փորձիր

1. Ավելացրու .row-ib { font-size: 0 } — երրորդ սյունը կբարձրանա՞։
2. Ջնջիր vertical-align: top-ը և տես, ինչ եղավ։
3. Փոխիր .i-ն inline-block-ի։
4. Նկատիր, որ display: none-ի տարրը ընդհանրապես չկա, իսկ մյուս երկուսի տեղը մնացել է։

09Դասարանական

Հորիզոնական մենյու — դասական օրինակ, թե ինչպես display-ը փոխում է ամեն ինչ։

HTML
<nav aria-label="Գլխավոր մենյու">
    <ul class="menu">
        <li><a href="#">Գլխավոր</a></li>
        <li><a href="#">Ապրանքներ</a></li>
        <li><a href="#">Մեր մասին</a></li>
        <li><a href="#">Կապ</a></li>
    </ul>
</nav>
քայլ առ քայլ
/* Քայլ 1 — li-երը դառնում են հորիզոնական */
.menu li {
    display: inline-block;
}

/* Քայլ 2 — հղումներին տալիս ենք padding
   (հնարավոր է, որովհետև global.css-ում
    a { display: inline-block } արդեն կա)   */
.menu a {
    padding: 12px 18px;
    color: var(--text);
    border-radius: 6px;
}

/* Քայլ 3 — վիճակներ */
.menu a:hover,
.menu a:focus-visible {
    background: var(--secondary);
    color: var(--on-dark);
}

.menu a.is-active {
    background: var(--light);
}
Ուշադրություն սեղմելի տարածքին

padding-ը դրված է հղումի վրա, ոչ li-ի։ Դրա շնորհիվ ամբողջ ուղղանկյունը սեղմելի է։

Եթե padding-ը լիներ li-ի վրա, օգտագործողը պիտի ուղիղ տառերին սեղմեր։ Հեռախոսում դա տառապանք է։ Նվազագույն հարմարավետ չափը՝ 44×44px։

Այս մենյուն ունի բացակի խնդիրը

li-երի միջև կան 4px բացակներ՝ HTML-ի տողադարձերից։ Մենյուի համար դա նույնիսկ լավ է թվում։ Բայց երբ պետք լինի ճշգրիտ վերահսկել բացակները — 11-րդ դասին կանցնենք Flexbox-ի, և այնտեղ gap: 10px-ը կլուծի ամեն ինչ։

10Տնային աշխատանք

  1. Ստեղծիր երեք բլոկ՝ block, inline, inline-block։ Ամեն մեկին տուր նույն width, height, margin։ Նկարագրիր տարբերությունները։
  2. Ցուցադրիր, որ inline-ի ուղղահայաց padding-ը նկարվում է, բայց տեղ չի զբաղեցնում։
  3. Կառուցիր երեք սյուն inline-block-ով և 33.33%-ով։ Ցույց տուր խնդիրը, ապա լուծիր բոլոր երեք ձևով։
  4. Ցուցադրիր vertical-align: top-ի ազդեցությունը տարբեր բարձրության բլոկների վրա։
  5. Համեմատիր display: none, visibility: hidden և opacity: 0։ Ապացուցիր, որ opacity: 0-ով կոճակը դեռ սեղմվում է։
  6. Օգտագործիր .visually-hidden դասը՝ բաժնի վերնագիր ավելացնելու համար, որը դիզայնում չկա։
  7. Ցուցադրիր overflow-ի չորս արժեքը՝ նույն երկար տեքստով։
  8. Վերցրու Դաս 3-ի աղյուսակը և փաթեթավորիր .table-wrap { overflow-x: auto }-ի մեջ։ Ստուգիր հեռախոսի ռեժիմում։
  9. Կառուցիր հորիզոնական մենյու դասարանական օրինակի պես։ Համոզվիր, որ սեղմելի տարածքը 44px-ից մեծ է։
  10. Կառուցիր էջ, որտեղ ամբողջ լայնությամբ header-ը և footer-ը block են, մենյուն՝ հորիզոնական, իսկ բովանդակությունը՝ կենտրոնացված max-width-ով։

11Հիշելու թերթիկ

Եվ մեկ բան պարզ դարձավ

Դաս 6-ի a { display: inline-block }-ը հիմա հասկանալի է․ առանց դրա հղումին չէիր կարող տալ padding և չափեր։ Ամեն կոճակ-հղում կախված է այդ մեկ տողից։

Ստուգաթերթ

  • Հղումների սեղմելի տարածքը ≥ 44×44px
  • padding-ը հղումի վրա է, ոչ li-ի
  • Չկա հորիզոնական սքրոլ ամբողջ էջի վրա
  • Լայն աղյուսակները փաթեթավորված են overflow-x: auto-ով
  • opacity: 0-ի փոխարեն օգտագործվում է display: none, երբ էլեմենտն իսկապես պետք չէ

Ինքնաստուգում

  • Կարո՞ղ եմ բացատրել, ինչու inline-ը չի ընդունում height
  • Գիտե՞մ, որտեղից է գալիս inline-block-ի 4px բացակը
  • Հասկանո՞ւմ եմ երեք թաքցնելու ձևերի տարբերությունը
  • Կարո՞ղ եմ բացատրել, ինչու inline-block-ը բավարար չէ դասավորության համար
Հաջորդ դասին — կարևոր անցում

Ավարտում ենք CSS-ի հիմունքները և անցնում դասավորության մեթոդաբանությանը։

Դաս 10-ը լինելու է բոլորովին այլ․ նոր հատկություններ չենք սովորի։ Փոխարենը կկառուցենք main > section > .row > .col > .wrapper համակարգը և կհասկանանք՝ ինչու հենց այսպես։ Դա այն կմախքն է, որի վրա կնստի մնացած ամեն ինչը։
