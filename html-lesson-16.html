01Խնդիրը

երեք միամիտ լուծում
/* ❌ 1. Միայն լայնություն — բարձրությունները տարբեր են */
.card img { width: 100%; }

/* ❌ 2. Երկուսն էլ — նկարը ձգվում և դեֆորմացվում է */
.card img { width: 100%; height: 200px; }

/* ❌ 3. Կտրում — նկարի կենտրոնը կորչում է */
.card picture { height: 200px; overflow: hidden; }
Բնօրինակ նկարներ width: 100% միայն ┌────────┐ ┌──────┐ ┌────────┐┌────────┐ │ │ │ │ │ ││ │ │ 4:3 │ │ 16:9 │ │ │└────────┘ │ │ └──────┘ │ │ քարտերի └────────┘ └────────┘ ներսում խառնաշփոթ
Ճիշտ լուծումը

Կոնտեյները սահմանում է չափը (aspect-ratio), նկարը լցնում է այն առանց դեֆորմացիայի (object-fit: cover)։

Երկու հատկություն, և խնդիրը լուծված է ընդմիշտ։

02object-fit

Ասում է՝ ինչպես նկարը պիտի տեղավորվի իրեն հատկացված տուփի մեջ։

հինգ արժեք
img { object-fit: fill; }        /* լռելյայն — ձգվում է ❌ */
img { object-fit: cover; }       /* լցնում է, ավելցուկը կտրվում ✅ */
img { object-fit: contain; }     /* ամբողջը երևում է, մնում է դատարկ տեղ */
img { object-fit: scale-down; }  /* contain, բայց չի մեծացնում */
img { object-fit: none; }        /* բնօրինակ չափը */
fill (լռելյայն) cover contain ┌──────────┐ ┌──────────┐ ┌──────────┐ │ ░░░░░░░░ │ │▓▓▓▓▓▓▓▓▓▓│ │ ▓▓▓▓▓▓ │ │ ░ձգված░░ │ │▓▓ լցված ▓│ │ ▓ամբող▓ │ │ ░░░░░░░░ │ │▓▓▓▓▓▓▓▓▓▓│ │ ▓▓▓▓▓▓ │ └──────────┘ └──────────┘ └──────────┘ դեֆորմացված համամասն, համամասն, ավելցուկը դատարկ շերտեր կտրված է կողքերին
object-fit-ը պահանջում է չափեր

object-fit-ը աշխատում է միայն այն դեպքում, երբ նկարն ունի և՛ width, և՛ height։ Առանց դրանց նկարը պարզապես ցուցադրվում է իր բնական չափով, և կտրելու բան չկա։

գործնական ձևանմուշ
.card picture {
    display: block;
    height: 200px;
}

.card img {
    width: 100%;
    height: 100%;
    object-fit: cover;
}

object-position

ո՞ր մասը պահել կտրելիս
img { object-position: center; }      /* լռելյայն */
img { object-position: top; }         /* դիմանկարների համար ⭐ */
img { object-position: 50% 30%; }
img { object-position: left bottom; }
Դիմանկարների կանոն

cover-ը կտրում է կենտրոնից։ Դիմանկարի դեպքում դա նշանակում է, որ գլուխը կարող է կտրվել։

object-position: top-ը պահում է վերին մասը։ Թիմի բաժնի համար դա գրեթե միշտ ճիշտ ընտրություն է։

03aspect-ratio

Ֆիքսված height: 200px-ի փոխարեն՝ համամասնություն, որը մասշտաբավորվում է ինքնաբերաբար։

ժամանակակից ձևը
.card picture {
    display: block;
    aspect-ratio: 4 / 3;    /* բարձրությունը հաշվարկվում է ինքնաբերաբար */
}

.card img {
    width: 100%;
    height: 100%;
    object-fit: cover;
}
ՀամամասնությունԵ՞րբ օգտագործել
1 / 1Ավատարներ, Instagram-ի ոճ
4 / 3Ապրանքների քարտեր
3 / 2Լուսանկարներ
16 / 9Վիդեո, hero-ներ
21 / 9Լայն բաններներ
Ինչո՞ւ aspect-ratio, ոչ ֆիքսված height

height: 200px — 375px էկրանին քարտը 355px լայն է, նկարը՝ 200px բարձր։ Համամասնությունը դառնում է գրեթե 16:9։ Իսկ 1440px էկրանին քարտը 300px է, և նույն 200px-ը դառնում է 3:2։

Նույն դիզայնը երկու տարբեր տեսքով։ aspect-ratio-ն պահում է համամասնությունը ամեն լայնության վրա։

Կարևոր կողմնակի օգուտ

aspect-ratio-ը (կամ HTML-ի width/height ատրիբուտները) ամրագրում է տեղը նկարի բեռնումից առաջ։

Առանց դրա էջը «ցատկում է», երբ նկարները բեռնվում են՝ տեքստը շարժվում է ներքև, և օգտագործողը սեղմում է սխալ տեղում։ Սա իրական խնդիր է, և Google-ը դա հաշվի է առնում կայքի գնահատականում։

04Ֆոնային նկարներ

hero-ի ձևանմուշ

    background-repeat: no-repeat;

Ուշադրություն ուղուն

CSS-ում ուղին հաշվվում է CSS ֆայլից, ոչ HTML-ից։

Եթե main.css-ը css/ թղթապանակում է, իսկ նկարը՝ images/-ում, ապա ուղին է ../images/hero.jpg։ Սա Դաս 2-ի ուղիների կանոնի ամենահաճախ մոռացվող կիրառությունն է։

05SVG

Վեկտորային ձևաչափ։ Նկարագրում է ձևերը, ոչ պիքսելները — ուստի ցանկացած չափի վրա մնում է սուր։

</svg>

fill: currentColor — ամենաօգտակար հնարքը

Արդյունքում պատկերակը ինքնաբերաբար ընդունում է կոճակի կամ հղումի գույնը՝ ներառյալ :hover վիճակում։ Մեկ SVG ֆայլ, տասնյակ գունային տարբերակ, զրո լրացուցիչ կոդ։

Հասանելիություն

Դեկորատիվ պատկերակ (կողքին տեքստ կա) → aria-hidden="true"
Իմաստ կրող պատկերակ (միայնակ կոճակի ներսում) → կոճակին տուր aria-label="Փակել"

Երբեք մի՛ թող պատկերակ-կոճակը առանց տեքստային բացատրության։

06srcset — ճիշտ չափը ճիշտ էկրանին

Խնդիրը

2400px լայնությամբ նկարը կշռում է 800 ԿԲ։ Հեռախոսում այն ցուցադրվում է 350px-ով — բայց ներբեռնվում է ամբողջությամբ։

Դանդաղ ինտերնետով դա 10+ վայրկյան սպասում մեկ նկարի համար։ Օգտագործողը կհեռանա։

srcset + sizes
<img
    src="images/laptop-800.jpg"
    srcset="images/laptop-400.jpg   400w,
            images/laptop-800.jpg   800w,
            images/laptop-1600.jpg 1600w"
    sizes="(max-width: 576px) 100vw,
           (max-width: 992px) 50vw,
           33vw"
    alt="Նոութբուք Pro բաց վիճակում"
    width="800" height="600">
ԱտրիբուտԻնչ է ասում բրաուզերին
srcՊահեստային տարբերակ հին բրաուզերների համար
srcset«Ահա ինչ չափերի ֆայլեր ունեմ»։ w = նկարի իրական լայնությունը
sizes«Ահա որքան տեղ կզբաղեցնի նկարը էկրանին»
Ինչպես է բրաուզերը որոշում

1. Կարդում է sizes-ը և հաշվում՝ 375px էկրանին նկարը կլինի 100vw = 375px։
2. Հաշվի է առնում էկրանի խտությունը՝ Retina-ի դեպքում ×2 = 750px։
3. Ընտրում է srcset-ից ամենամոտ չափը՝ 800w։

Ամեն ինչ ավտոմատ։ Քո գործը՝ պատրաստել ֆայլերը և ճիշտ նկարագրել։

sizes-ը կրկնում է քո media query-ները

Նկատեցի՞ր՝ 576px և 992px-ը նույն breakpoint-ներն են, ինչ Դաս 14-ում։ Իսկ 100vw / 50vw / 33vw-ն համապատասխանում է w-sm-100 / w-md-50 / w-33-ին։

Այսինքն՝ sizes-ը պարզապես նույն տրամաբանության վերապատմումն է բրաուզերի համար։

07<picture>

Երբ պետք է ոչ թե նույն նկարի տարբեր չափեր, այլ տարբեր ֆայլեր։

1. Ժամանակակից ձևաչափեր
<picture>
    <source srcset="images/hero.avif" type="image/avif">
    <source srcset="images/hero.webp" type="image/webp">
    <img src="images/hero.jpg" alt="Աշխատասենյակ նոութբուքով">
</picture>
Ինչպես է աշխատում

Բրաուզերը կարդում է source-երը վերևից ներքև և վերցնում առաջինը, որը հասկանում է։ Եթե ոչ մեկը՝ ընկնում է <img>-ի վրա։

Այսինքն՝ ժամանակակից բրաուզերը կվերցնի AVIF-ը (ամենաթեթևը), հինը՝ JPG-ն։ <img>-ը պարտադիր է — այն վերջին ապահովագրությունն է և կրում է alt-ը։

2. Արտիստիկ կադրավորում
<picture>
    <!-- Հեռախոսում՝ ուղղահայաց կադր -->
    <source media="(max-width: 576px)"
            srcset="images/hero-mobile.jpg">

    <!-- Համակարգչում՝ լայն կադր -->
    <img src="images/hero-wide.jpg" alt="Աշխատասենյակ">
</picture>
Ինչո՞ւ է սա պետք

Լայն 21:9 բանները հեռախոսում դառնում է բարակ շերտ, որտեղ ոչինչ չի երևում։ Պարզապես փոքրացնելը չի օգնի — պետք է ուրիշ կադր՝ մոտեցված, ուղղահայաց։

Դա կոչվում է art direction։ srcset-ը լուծում է քաշի խնդիրը, <picture media>-ն՝ կոմպոզիցիայի։

ԽնդիրԼուծում
Նույն նկարը, տարբեր չափերsrcset + sizes
Ժամանակակից ձևաչափեր<picture> + type
Տարբեր կադրավորում<picture> + media

08Օպտիմիզացիա

ՁևաչափՀարաբերական քաշԵ՞րբ
PNG100%Թափանցիկություն, սուր եզրեր
JPG~30%Լուսանկարներ (ունիվերսալ)
WebP~20%Ամեն ինչ, բացի հին բրաուզերներից
AVIF~12%Ամենաթեթևը, աջակցությունը լավն է
SVGՉափից անկախԼոգոներ, պատկերակներ

Ստուգաթերթ ամեն նկարի համար

  • Չափը չի գերազանցում իրական ցուցադրման չափը × 2
  • Ձևաչափը ճիշտ է ընտրված
  • Ֆայլը սեղմված է (squoosh.app կամ tinypng.com)
  • Կա alt
  • Կան width և height ատրիբուտները
  • Էկրանից դուրս նկարներն ունեն loading="lazy"
ուշացումով բեռնում
<!-- Առաջին էկրանի նկարներ — ԱՌԱՆՑ lazy -->
<img src="images/hero.jpg" alt="..." fetchpriority="high">

<!-- Ներքևի նկարներ — lazy -->
<img src="images/product-5.jpg" alt="..." loading="lazy">
Հաճախ սխալ են անում

loading="lazy" առաջին էկրանի նկարի վրա → այն սկսում է բեռնվել ուշ, և օգտագործողը տեսնում է դատարկ տեղ։

Կանոն՝ lazy միայն այն նկարներին, որոնք սկզբում չեն երևում։

Ինչպես ստուգել

DevTools → Network → Img ֆիլտր → թարմացրու էջը։

Կտեսնես ամեն նկարի քաշը և բեռնման ժամանակը։ Եթե որևէ մեկը 300 ԿԲ-ից ծանր է — հավանաբար այն պիտի սեղմել։ Ընդհանուր էջը լավ է, երբ 1 ՄԲ-ից պակաս է։

09Խաղահրապարակ

Սավառնիր կոճակի վրայով — պատկերակը փոխում է գույնը
Փորձիր

1. Ջնջիր .frame img { height: 100% }-ը — object-fit-ը կաշխատի՞։
2. Փոխիր .pos-top-ը bottom-ի։
3. Փոխիր .ratio-16-9-ը 21 / 9-ի։
4. Ջնջիր .icon { fill: currentColor }-ը և սավառնիր կոճակի վրայով։

10Դասարանական

Վերցնում ենք ապրանքների բաժինը և կարգի ենք բերում նկարները։

css/global.css — այսօրվա ավելացումը
/* ---------- Նկարների օգնականներ ---------- */
.img-cover {
    width: 100%;
    height: 100%;
    object-fit: cover;
}

.img-contain {
    width: 100%;
    height: 100%;
    object-fit: contain;
}

.ratio-1-1  { aspect-ratio: 1 / 1; }
.ratio-4-3  { aspect-ratio: 4 / 3; }
.ratio-3-2  { aspect-ratio: 3 / 2; }
.ratio-16-9 { aspect-ratio: 16 / 9; }
HTML
<div class="col w-33 w-md-50 w-sm-100">
    <article class="wrapper">

        <picture class="ratio-4-3">
            <source srcset="images/laptop.webp" type="image/webp">
            <img class="img-cover"
                 src="images/laptop.jpg"
                 alt="Նոութբուք Pro 14 բաց վիճակում"
                 width="800" height="600"

        </picture>

        <div class="card__body">
            <h3 class="title-4 mb-10">Նոութբուք Pro 14</h3>
            <p class="price">450&nbsp;000 ֏</p>
        </div>

    </article>
</div>
Ուշադրություն՝ picture-ը հիմա կրում է aspect-ratio-ն

Դաս 8-ից global.css-ում ունենք picture { display: block }։ Դրա շնորհիվ aspect-ratio-ն աշխատում է դրա վրա։

Կառուցվածքը՝ picture սահմանում է կադրի ձևը, img լցնում է այն։ Նույն տրամաբանությունը, ինչ .col-ի և .wrapper-ի դեպքում — ամեն շերտն իր գործն է անում։

  1. Ավելացրու global.css-ի նոր դասերը
  2. Փաթեթավորիր բոլոր նկարները <picture>-ի մեջ
  3. Ավելացրու ratio-* դասը picture-ին
  4. Ավելացրու img-cover դասը img-ին
  5. Ավելացրու width, height, loading="lazy"
  6. Ստուգիր, որ բոլոր alt-երը իմաստալից են
  7. Բացիր DevTools → Network → Img և ստուգիր քաշերը

11Տնային աշխատանք

  1. Վերցրու 6 նկար բոլորովին տարբեր չափերի։ Ցուցադրիր դրանք նույն ցանցում՝ aspect-ratio + object-fit: cover-ով։
  2. Ցուցադրիր object-fit-ի հինգ արժեքը՝ նույն նկարով։ Նկարագրիր ամեն մեկը։
  3. Գտիր դիմանկար, որտեղ cover-ը կտրում է գլուխը։ Ուղղիր object-position-ով։
  4. Համեմատիր height: 200px-ը և aspect-ratio: 4/3-ը՝ նեղացնելով պատուհանը։ Ուղարկիր երկու սքրինշոթ։
  5. Կառուցիր hero՝ ֆոնային նկարով և գրադիենտ շերտով՝ մեկ background-image հատկությամբ։
  6. Գտիր անվճար SVG պատկերակներ (օր.՝ Feather Icons)։ Ներդրիր երեքը inline և գունավորիր fill: currentColor-ով։
  7. Ստեղծիր կոճակ պատկերակով, որի գույնը փոխվում է :hover-ի ժամանակ։
  8. Պատրաստիր մեկ նկարի երեք չափ (400/800/1600) և գրիր srcset + sizes։ Ստուգիր DevTools-ով՝ որ ֆայլն է բեռնվում տարբեր լայնություններում։
  9. Փոխարկիր 5 նկար WebP-ի (squoosh.app)։ Համեմատիր քաշերը և գրիր տոկոսային տարբերությունը։
  10. Ամբողջ էջում ավելացրու loading="lazy" ներքևի նկարներին։ Չափիր բեռնման ժամանակը DevTools → Network-ում՝ առաջ և հետո։

12Հիշելու թերթիկ

ՀատկությունԻնչ է անում
object-fit: coverԼցնում է առանց դեֆորմացիայի ⭐
object-fit: containԱմբողջը երևում է
object-position: topԴիմանկարների համար
aspect-ratio: 4 / 3Կայուն համամասնություն ⭐
background-size: coverՖոնի համար
fill: currentColorSVG-ն վերցնում է տեքստի գույնը ⭐
srcset + sizesՃիշտ չափը ճիշտ էկրանին
<picture> + typeWebP / AVIF
<picture> + mediaԱյլ կադրավորում
loading="lazy"Միայն էկրանից դուրս նկարներին
width + heightԱմրագրում է տեղը, էջը չի ցատկում ⭐

Հիմնական ձևանմուշը

<picture class="ratio-4-3"> <img class="img-cover" src="..." alt="..." width="800" height="600" loading="lazy"> </picture> picture → սահմանում է կադրի ձևը img → լցնում է այն

Ի՞նչ ավելացավ global.css-ում այսօր

✓ .img-cover / .img-contain ✓ .ratio-1-1 / .ratio-4-3 / .ratio-3-2 / .ratio-16-9

Ստուգաթերթ

  • Բոլոր նկարներն ունեն alt
  • Բոլոր նկարներն ունեն width և height
  • Կադրերի համամասնությունը միատեսակ է
  • Ոչ մի նկար չի ձգված
  • Դիմանկարներում գլուխները չեն կտրված
  • Էկրանից դուրս նկարներն ունեն loading="lazy"
  • Առաջին էկրանի նկարներն չունեն lazy
  • Ոչ մի ֆայլ 300 ԿԲ-ից ծանր չէ
  • Լոգոն և պատկերակները SVG են
  • Էջը բեռնվելիս չի «ցատկում»

Ինքնաստուգում

  • Կարո՞ղ եմ բացատրել cover-ի և contain-ի տարբերությունը
  • Գիտե՞մ, ինչու aspect-ratio, ոչ ֆիքսված height
  • Հասկանո՞ւմ եմ, ե՞րբ <img>, ե՞րբ background-image
  • Գիտե՞մ, ինչ է անում currentColor-ը
  • Կարո՞ղ եմ բացատրել srcset-ի և <picture media>-ի տարբերությունը
Հաջորդ դասին

Կոմպոնենտներ․ քարտեր, կոճակների համակարգ, պիտակներ, ::before և ::after, ստվերներ։ Կհավաքենք այն ամենը, ինչ սովորել ենք, կրկնվող կոմպոնենտների գրադարանում։
