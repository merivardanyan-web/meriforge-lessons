## Հարձակումներ, որ կայքը կանգնեցնում է

```bash
# CSRF․ POST առանց token-ի
$ curl -si -X POST https://…/bookings -d "slot_id=1" | head -1
HTTP/1.1 419 unknown status

# API-ն չի բացահայտում անձնական տվյալներ
$ curl -s "https://…/api/slots?date=2026-10-23&staff=2"
{"data":[{"id":38,"time":"11:00","starts_at":"2026-10-23T11:00:00+04:00","staff":{"id":2,"name":"Արամ Հակոբյան"}}, …],
 "meta":{"date":"2026-10-23","label":"ուրբաթ, 23 հոկտեմբերի","count":7}}

$ curl -s -H "Accept: application/json" "https://…/api/slots?date=2020-01-01"
```

## Կրկնակի ամրագրում ⭐

**Զուգահեռ հարցումներ։** 6 տարբեր հաճախորդ, նույն ժամ, նույն պահին (6 thread, 4 PHP worker)․

```
POST /bookings  →  /my/bookings                       ← 1 հաջողություն
POST /bookings  →  /services/sanrvatsq-moruq  × 5    ← «Այս ժամը հենց նոր զբաղեցրեցին։ Ընտրիր ուրիշը։»

SELECT COUNT(*) FROM bookings WHERE active_slot_id = 171;   → 1
```

**Բազան ինքը։** HeidiSQL-ում նույն `active_slot_id`-ով երկրորդ տող․

```sql
INSERT INTO bookings (user_id, time_slot_id, service_id, active_slot_id, price, status, created_at, updated_at)
VALUES (4, 171, 3, 171, 1, 'booked', NOW(), NOW());
-- ERROR 1062 (23000): Duplicate entry '171' for key 'bookings_active_slot_id_unique'
```

Սա պաշտպանության ժամանակ ցույց տալու լավագույն ապացույցն է․ ոչ թե «PHP-ն ստուգում է», այլ «բազան չի թողնում»։
