Git և GitHub

Այսօր JS չենք գրում։ Սովորում ենք այն գործիքը, առանց որի ոչ մի ծրագրավորող չի աշխատում։ Դասի վերջում քո կատալոգը կլինի ինտերնետում՝ իսկական հասցեով։

Նախապայման՝ Դաս 15–16-ի նախագիծ Առանձին դաս · գործիքներ Արդյունք՝ հրապարակված կայք

00Ի՞նչ ենք սովորելու այսօր

  • Ինչո՞ւ է պետք տարբերակների կառավարումը
  • Git-ի երեք տարածքը
  • init, status, add, commit, log
  • .gitignore
  • Ճյուղեր՝ branch, switch, merge
  • Կոնֆլիկտներ և դրանց լուծումը
  • GitHub՝ remote, push, pull, clone
  • Կայքի հրապարակում GitHub Pages-ով

01Ինչո՞ւ է պետք Git-ը

Ծանո՞թ է այս պատկերը։

առանց Git-ի
catalog/
catalog_2/
catalog_նոր/
catalog_վերջնական/
catalog_վերջնական_2/
catalog_ՎԵՐՋՆԱԿԱՆ_իսկապես/
catalog_աշխատողը.zip

Եվ ամենասարսափելի հարցը՝ «ո՞րն էր այն, որտեղ ֆիլտրերն աշխատում էին»։

Git-ը լուծում է հենց այս խնդիրը։ Այն պահում է քո նախագծի ամբողջ պատմությունը․ ամեն փոփոխություն, ամեն օր, ամեն տարբերակ։ Ցանկացած պահի կարող ես․

  • տեսնել՝ ի՞նչ փոխվեց և ե՞րբ
  • վերադառնալ ցանկացած հին վիճակի
  • փորձարկել նոր գաղափար՝ առանց աշխատող տարբերակը վնասելու
  • աշխատել թիմով՝ առանց իրար կոդը ջնջելու
Git ≠ GitHub

Git — ծրագիր քո համակարգչում, որը հետևում է փոփոխություններին։
GitHub — կայք, որտեղ կարող ես պահել քո Git պահոցները ինտերնետում։
Git-ը կարող ես օգտագործել առանց GitHub-ի։ GitHub-ը՝ առանց Git-ի՝ ոչ։

Որտե՞ղ գրել հրամանները

VS Code-ում սեղմիր Ctrl + ` (հակադարձ ապաթարց) — կբացվի ներկառուցված տերմինալը հենց քո նախագծի թղթապանակում։ Դա ամենահարմար ձևն է։

Էլ. հասցեն

Օգտագործիր նույն հասցեն, որով գրանցվելու ես GitHub-ում։ Հակառակ դեպքում քո commit-երը այնտեղ չեն կապվի քո պրոֆիլին։

03Երեք տարածքը

Սա Git-ի ամենակարևոր գաղափարն է։ Եթե սա հասկանաս, մնացածը հեշտ կլինի։

ճանապարհը
  Working Directory        Staging Area          Repository
  (քո ֆայլերը)            (պատրաստվող փաթեթ)    (պատմությունը)

     main.js  ──── git add ────►  main.js  ──── git commit ────►  📦
     style.css                                                    📦
     index.html                                                   📦

Համեմատություն՝ ծանրոց ուղարկելը․

  • Working Directory — սեղանիդ վրայի իրերը։ Դու դրանք փոխում ես ազատ։
  • Staging Area — տուփը, որի մեջ դնում ես այն, ինչ ուզում ես ուղարկել։ Կարող ես դնել և հանել։
  • Repository — ուղարկված ծանրոցը։ Այն արդեն պատմության մեջ է և չի կորչի։
Ինչո՞ւ է պետք միջանկյալ քայլը

Որովհետև հաճախ մի քանի բան ես փոխում միաժամանակ։ Staging-ը թույլ է տալիս մեկ commit-ում դնել միայն ֆիլտրերի կոդը, իսկ զամբյուղինը՝ առանձին commit-ում։ Այդպես պատմությունը մնում է կարգին։

git diff --staged        # Staging vs վերջին commit

Եթե չգիտես՝ ինչ ես անում, նախ արա commit։ Commit արված ամեն ինչ գրեթե միշտ վերականգնելի է։ Commit չարվածը՝ ոչ։

07Ճյուղեր

Ճյուղը զուգահեռ իրականություն է։ Փորձարկում ես նոր գաղափար, և եթե չստացվի՝ պարզապես ջնջում ես ճյուղը։ Հիմնական տարբերակը մնում է անվնաս։

գծապատկեր
                    ● ── ● ── ●   feature/wishlist
                   /             \
main  ● ── ● ── ● ──────────────── ●
                                 merge
հիմնական հրամանները
git branch                          # ցուցակ
git branch feature/wishlist         # ստեղծել
git switch feature/wishlist         # անցնել

# Կամ երկուսը միասին
git switch -c feature/wishlist

# ... աշխատում ենք, commit ենք անում ...

# Վերադառնում ենք և միացնում
git switch main
git merge feature/wishlist

# Ջնջում ենք ավելորդ ճյուղը
git branch -d feature/wishlist
Ճյուղերի անվանում

Ընդունված է՝ feature/անուն — նոր հնարավորություն, fix/անուն — սխալի ուղղում։ Օրինակ՝ feature/cart, fix/search-case։

08Կոնֆլիկտներ

Կոնֆլիկտ է լինում, երբ երկու ճյուղում փոխվել է նույն ֆայլի նույն տողը։ Git-ը չգիտի՝ որն ընտրի, և հարցնում է քեզ։

ինչ ես տեսնում ֆայլում
<<<<<<< HEAD
const SEARCH_DELAY = 300;
=======
const SEARCH_DELAY = 500;
>>>>>>> feature/wishlist

Վերևում՝ քո ընթացիկ ճյուղի տարբերակը։ Ներքևում՝ միացվողի։ Քո գործն է․

  1. Ջնջել <<<<<<<, =======, >>>>>>> տողերը
  2. Թողնել ճիշտ տարբերակը (կամ գրել նոր, երրորդ)
  3. Պահպանել ֆայլը
  4. git add և git commit
Մի՛ վախեցիր

Կոնֆլիկտը սխալ չէ։ Դա Git-ի ազնիվ խոստովանությունն է՝ «այստեղ միայն դու կարող ես որոշել»։ VS Code-ը ցույց է տալիս հարմար կոճակներ՝ «Accept Current», «Accept Incoming», «Accept Both»։

09GitHub

Քայլ 1 — պահոց ստեղծել

  1. Գրանցվիր github.com-ում
  2. Սեղմիր New repository
  3. Անուն՝ catalog
  4. Ընտրիր Public
  5. Մի՛ նշիր «Add a README» — մեր պահոցն արդեն ունի ֆայլեր
  6. Սեղմիր Create repository
քայլ 2 — կապել և ուղարկել
# Կապում ենք տեղական պահոցը GitHub-ի հետ
git remote add origin https://github.com/ani/catalog.git

# Ստուգում ենք
git remote -v

# Ուղարկում ենք առաջին անգամ
git push -u origin main

# Հետագայում բավական է

-u — «հիշիր այս կապը», որ հետո միայն git push գրես։

# Ներբեռնել ուրիշի (կամ քո) նախագիծը զրոյից

Աշխատանքի ռիթմ

Օրվա սկզբում՝ git pull։ Օրվա վերջում՝ git push։ Այս սովորությունը կփրկի քեզ բազում կոնֆլիկտներից, երբ սկսես թիմով աշխատել։

10Հրապարակում · GitHub Pages

Ամենահաճելի մասը։ GitHub-ը կարող է քո ստատիկ կայքը ցուցադրել ինտերնետում՝ անվճար։

  1. Բացիր քո պահոցը GitHub-ում
  2. Վերևից՝ Settings
  3. Ձախ մենյուից՝ Pages
  4. Source → ընտրիր Deploy from a branch
  5. Branch → main, թղթապանակ՝ / (root)
  6. Սեղմիր Save
  7. Սպասիր 1–2 րոպե և թարմացրու էջը
քո հասցեն
https://ՔՈ-ՕԳՏԱՆՈՒՆԸ.github.io/catalog/
Հաճախ հանդիպող խնդիրներ

Էջը դատարկ է։ Հիմնական ֆայլը պիտի կոչվի ուղիղ index.html և լինի պահոցի արմատում։
CSS-ը չի բեռնվում։ Ուղիները պիտի լինեն հարաբերական՝ css/style.css, ոչ /css/style.css։
Հին տարբերակն է երևում։ Սպասիր մի քանի րոպե, ապա թարմացրու Ctrl + Shift + R-ով։
404։ Ստուգիր՝ պահոցը Public է, և Pages-ը միացված է։

Հետագա թարմացումները

Այսուհետ ամեն git push-ից 1–2 րոպե հետո կայքն ինքնաբերաբար կթարմանա։ Փոխեցիր կոդը → commit → push → կայքը նոր է։

11Դասարանական · քո կատալոգը ինտերնետում

Անցիր այս քայլերով քո Դաս 16-ի նախագծի հետ։

ամբողջ ճանապարհը
# 1. Մտնում ենք նախագիծ
cd catalog

# 2. Ստեղծում ենք պահոց
git init
git status

# 3. Ստեղծում ենք .gitignore (ձեռքով, խմբագրիչում)

# 4. Առաջին commit
git add .
git commit -m "Ապրանքների կատալոգ՝ ֆիլտրերով և զամբյուղով"

# 5. Կապում ենք GitHub-ի հետ
git remote add origin https://github.com/ՕԳՏԱՆՈՒՆ/catalog.git
git push -u origin main

# 6. Միացնում ենք Pages-ը կայքից (Settings → Pages)

# 7. Փոփոխություն ենք անում և ստուգում ամբողջ ցիկլը
#    (փոխիր ինչ-որ բան կոդում)
git status
git diff
git add .
git commit -m "Ավելացվել է վարկանիշով տեսակավորումը"
git push

# 8. Փորձարկում ենք ճյուղ
git switch -c feature/wishlist
#    (ավելացրու սրտիկի կոճակ)
git add .
git commit -m "Ավելացվել է հավանածների ցուցակը"
git switch main
git merge feature/wishlist
git push
git branch -d feature/wishlist

# Ապրանքների կատալոգ

Վեբ հավելված ֆիլտրերով, որոնմամբ և զամբյուղով։

## Դիտել
https://ՕԳՏԱՆՈՒՆ.github.io/catalog/

## Հնարավորություններ
- Ֆիլտր ըստ կատեգորիայի
- Որոնում debounce-ով
- Տեսակավորում գնով, անունով, վարկանիշով
- Զամբյուղ՝ պահպանմամբ localStorage-ում

## Տեխնոլոգիաներ
HTML, CSS (Flexbox), JavaScript (ES6+)

## Հեղինակ
Անուն Ազգանուն
Ինչո՞ւ է README-ն կարևոր

GitHub-ը այն ցուցադրում է պահոցի գլխավոր էջում։ Սա այն առաջին բանն է, որ տեսնում է ցանկացած մարդ՝ ուսուցիչ, ընկեր կամ ապագա գործատու։ Նախագիծ առանց README-ի կիսատ է թվում։

12Տնային աշխատանք

Մինի-նախագիծ

Այս տնայինի գլխավոր մասը՝ «Կայքը GitHub-ում», քայլ առ քայլ, starter ֆայլերով և պատրաստի օրինակով։ Ներքևի ցուցակի մնացած կետերը առանձին վարժություններ են։

Նախագիծ · Առաջադրանք 2

Հրապարակիր ՏեխնոՄարկետը․ Առաջադրանք 2, բաժին 01։

  1. Կարգավորիր Git-ը՝ user.name և user.email։ Ուղարկիր git config --global --list-ի արդյունքի սքրինշոթը։
  2. Հրապարակիր քո կատալոգը GitHub Pages-ով։ Ուղարկիր աշխատող հասցեն։
  3. Գրիր README.md՝ նկարագրությամբ, հնարավորությունների ցուցակով և հասցեով։
  4. Կատարիր առնվազն 5 իմաստալից commit՝ առանձին փոփոխություններով։ Ուղարկիր git log --oneline-ի արդյունքը։
  5. Ստեղծիր feature/ ճյուղ, ավելացրու նոր հնարավորություն, միացրու main-ին և ջնջիր ճյուղը։
  6. Դիտավորյալ ստեղծիր կոնֆլիկտ․ երկու ճյուղում փոխիր նույն տողը և միացրու։ Լուծիր և նկարագրիր՝ ինչ արեցիր։
  7. Ավելացրու .gitignore առնվազն 5 կանոնով։
  8. Հրապարակիր նաև քո HTML/CSS բլոկի նախագծերից մեկը՝ առանձին պահոցում։
  9. Փորձիր git clone-ը՝ ներբեռնիր քո սեփական պահոցը ուրիշ թղթապանակում և համոզվիր, որ ամեն ինչ տեղում է։
  10. Գտիր GitHub-ում որևէ հետաքրքիր բաց նախագիծ, նայիր դրա README-ն և commit-երի պատմությունը։ Գրիր՝ ի՞նչ նկատեցիր։
