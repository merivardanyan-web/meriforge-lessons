02Հինգ գաղափար, որոնք կմնան

CSS հատկությունները կփոխվեն։ Այս հինգը՝ ոչ։

1. Պատասխանատվությունների բաժանում
/* Ամեն շերտ մեկ գործ է անում */

section   → ֆոն, ուղղահայաց բացակ
.row      → պատեր, դասավորության ուղղություն
.col      → լայնություն, բացակներ
.wrapper  → տեսք

   Նույնը PHP-ում՝ MVC = Model, View, Controller */
2. Վարքագիծ ≠ արժեք

Ախտորոշման կարգը

Երբ ինչ-որ բան չի աշխատում, անցիր այս հերթականությամբ․

1. Բացիր DevTools և ընտրիր էլեմենտը
2. Styles վահանակում նայիր՝ կանոնը կիրառվե՞լ է (եթե ջնջված է — սպեցիֆիկություն)
3. Computed ներդիրում նայիր իրական արժեքը
4. Box model դիագրամում նայիր չափերը
5. Ստուգիր ծնողներին — position, overflow, display

90% դեպքերում պատասխանը գտնվում է առաջին երկու քայլում։

04Ինքնագնահատում

Ազնվորեն։ Ոչ ոք չի տեսնի, բացի քեզնից։

Մակարդակ 1 — հասկանում եմ

  • Կարող եմ բացատրել, ինչ է box-sizing: border-box-ը և ինչու
  • Գիտեմ Flexbox-ի երկու առանցքը
  • Հասկանում եմ սպեցիֆիկությունը
  • Կարող եմ բացատրել, ինչու rem, ոչ px
  • Գիտեմ absolute-ի և relative-ի կապը

Մակարդակ 2 — կարող եմ անել

  • Կառուցում եմ ադապտիվ ցանց առանց նայելու
  • Կենտրոնացնում եմ բլոկը երկու առանցքով
  • Կառուցում եմ քարտ՝ կոճակը ներքևում
  • Ստուգում եմ կոնտրաստը DevTools-ով
  • Գտնում եմ հորիզոնական սքրոլի պատճառը

Մակարդակ 3 — կարող եմ որոշել

  • Ընտրում եմ Grid-ի և Flex-ի միջև՝ հիմնավորելով
  • Որոշում եմ, ե՞րբ utility, ե՞րբ կոմպոնենտ
  • Գտնում եմ սանդղակը խառը չափումներից
  • Ընտրում եմ breakpoint-ը ըստ բովանդակության, ոչ սարքի
  • Գիտեմ, ե՞րբ clamp(), ե՞րբ media query

Մակարդակ 4 — մտածում եմ օգտագործողի մասին

  • Ստուգում եմ ամեն էջ Tab-ով
  • Գրում եմ իմաստալից alt
  • Հարգում եմ prefers-reduced-motion-ը
  • Մտածում եմ դանդաղ ինտերնետի մասին
  • Փաստագրում եմ սահմանափակումները

Կարևոր

Առաջին երկու մակարդակը գիտելիք են։ Երրորդն ու չորրորդը՝ մասնագիտություն։

Շատերը կանգ են առնում երկրորդում՝ գիտեն հատկությունները, բայց ամեն նոր նախագծում սկսում են զրոյից և պատահական որոշումներ են կայացնում։

Տարբերությունը հենց այնտեղ է։

05Ի՞նչ չսովորեցինք

Ազնվորեն՝ շատ բան։ Ահա ցուցակը և պատճառները։

ԹեմաԻնչո՞ւ ոչ
Sass / SCSSCSS փոփոխականներն ու ներդրվածությունը հիմա բավական են։ Sass-ը սովորվում է մեկ երեկոյում, երբ հասկանում ես մաքուր CSS-ը
TailwindՄենք արդեն կառուցեցինք utility-համակարգ ձեռքով։ Tailwind-ը նույն գաղափարն է՝ պատրաստի
BootstrapՆույն պատճառով։ Հիմա գիտես, ինչպես է աշխատում դրա grid-ը
Container queriesՆոր է։ Կպետք գա կոմպոնենտային մոտեցումների դեպքում
CSS Layers, :has()Օգտակար, բայց մեծ նախագծերի համար
Անիմացիաների գրադարաններGSAP, Framer Motion — JS-ից հետո
ԴիզայնԱռանձին մասնագիտություն է։ Մենք սովորեցինք իրականացնել դիզայնը, ոչ ստեղծել այն
Ինչո՞ւ մաքուր CSS, ոչ գրադարան

Գրադարանով սկսողը արագ արդյունք է ստանում, բայց չի հասկանում, ինչու է այն աշխատում։ Երբ ինչ-որ բան կոտրվի — փակուղի է։

Դու հիմա կարող ես բացել Bootstrap-ի կոդը և կարդալ այն։ Կտեսնես նույն .row, .col, box-sizing, flex։

Գրադարանը գործիք է, ոչ փոխարինող։

06Կամուրջ JavaScript-ին

Մեր էջը գեղեցիկ է և հասանելի։ Բայց այն ոչինչ չի անում։

Ինչ ունենք հիմաԻնչ կավելանա JS-ով
Բուրգեր՝ checkbox-ովՃիշտ մենյու՝ Esc, դրսում սեղմում, aria-expanded
Ապրանքները՝ HTML-ում ձեռքովՑուցակ տվյալներից՝ render()
Չկա որոնումՖիլտր, տեսակավորում, որոնում
«Գնել» կոճակը ոչինչ չի անումԶամբյուղ՝ հաշվիչով և գումարով
Ֆորման չի ուղարկվումՎալիդացիա և ուղարկում
Թեմայի անջատիչը թերի էlocalStorage՝ ընտրությունը հիշվում է
Ապրանքները ֆիքսված ենfetch՝ տվյալներ սերվերից
Ի՞նչ կմնա անփոփոխ

Ամբողջ CSS-ը։

JS-ը փոխում է դասերը և բովանդակությունը, ոչ ոճերը։ .card, .btn--primary, .is-open — դրանք բոլորը մնում են։

Դրա համար ենք սովորել .is-active, .is-open ձևի դասերը՝ դրանք հենց JS-ի համար են։ Երկրորդ բլոկում կտեսնես, ինչպես։

Վերջին միտքը

CSS-ը հաճախ համարում են «հեշտ» մասը։ Դա սխալ է։

Հեշտ է գրել CSS, որն աշխատում է մեկ էկրանին։ Դժվար է գրել CSS, որը չի փլվում՝ երբ բովանդակությունը փոխվում է, երբ էկրանը նեղանում է, երբ վեց ամիս անց վերադառնում ես ֆայլին։

Դու սովորեցիր հենց երկրորդը։ Հատկությունները քեզ մոտ միշտ կլինեն որոնման հեռավորության վրա։ Համակարգային մտածողությունը՝ ոչ։
