JS-ը կարելի է անջատել, փոփոխել Console-ում, շրջանցել։ Ուստի բրաուզերի վալիդացիան անվտանգություն չէ (HTML Դաս 4)։

PHP-ի կոդին օգտագործողը չի հասնում։ Դրա համար ամեն կարևոր ստուգում պիտի կրկնվի սերվերում։ Դա կլինի Դաս 6-ի հիմնական թեման։

ի՞նչ է տեսնում բրաուզերը
<!-- Այն, ինչ գրում ես -->
<h1><?= "Բարև, " . $name ?></h1>

<!-- Այն, ինչ ստանում է բրաուզերը -->
<h1>Բարև, Անի</h1>
PHP-ն HTML գեներատոր է

Սա ամենակարևոր մտավոր մոդելն է սկզբում։ PHP-ն «չի աշխատում էջում» — այն գրում է էջը, ապա անհետանում։

Երբ բրաուզերը ստանում է պատասխանը, PHP-ի կոդն արդեն կատարված է և չկա։ Ոչ մի onclick, ոչ մի արձագանք — դրա համար է JavaScript-ը։

02Հարցում → պատասխան

1. Օգտագործողը մուտքագրում է հասցեն │ 2. Բրաուզերը ուղարկում է HTTP հարցում │ 3. Սերվերը (Apache) ստանում է այն │ 4. Տեսնում է .php ընդլայնումը → փոխանցում է PHP-ին │ 5. PHP-ն կատարում է կոդը · կարող է դիմել MySQL-ին · կարող է կարդալ ֆայլեր · արդյունքում գեներացնում է HTML │ 6. Apache-ն ուղարկում է HTML-ը բրաուզերին │ 7. Բրաուզերը նկարում է էջը → այստեղ սկսում է աշխատել JS-ը PHP-ի կյանքը՝ 5-րդ քայլը։ Միլիվայրկյաններ։
Ամեն հարցում՝ մաքուր էջ

PHP-ն ոչինչ չի հիշում հարցումների միջև։ Ամեն անգամ սկրիպտը սկսվում է զրոյից՝ բոլոր փոփոխականները դատարկ։

Դա տարբերվում է JS-ից, որտեղ էջը բաց մնալիս վիճակը պահպանվում է։ Հիշելու համար պետք են սեսիաներ (Դաս 7) կամ տվյալների բազա (Դաս 8)։

03PHP-ի ներկառուցված սերվերը

Նախքան բանդլ տեղադրելը՝ տեսնենք, թե ինչ է PHP-ն ինքնին։

տերմինալ
# Ստուգում — կա՞ PHP համակարգում
php -v

# Ստեղծիր թղթապանակ մեկ ֆայլով՝ index.php
# Ապա այդ թղթապանակում՝
php -S localhost:8000

# Բացիր բրաուզերում՝ http://localhost:8000
Ի՞նչ եղավ հենց հիմա

PHP-ն սովորական ծրագիր է, ինչպես Node.js-ը։ php -S-ը գործարկեց փոքրիկ վեբ-սերվեր, որը լսում է 8000 պորտը։

Ոչ մի կախարդանք։ Երբ փակես տերմինալը, սերվերը կանհետանա։

Ինչո՞ւ սա բավարար չէ

Ներկառուցված սերվերը զարգացման խաղալիք է, ոչ իրական Apache։

· Չկա .htaccess և mod_rewrite → Դաս 14-ի Router-ը չի աշխատի
· Չկա MySQL
· Չկա phpMyAdmin
· Չի աշխատում մի քանի հարցում միաժամանակ

Ուստի տեղադրում ենք բանդլ։ Բայց հիմա գիտես, որ բանդլը մեկ ծրագիր չէ։

Երեք առաջին սխալը

06Դեբագ · քո նոր Console-ը

JS-ում ունեիր console.log և DevTools։ Այստեղ գործիքներն այլ են։

սխալների ցուցադրում — առաջին բանը
<?php
// Զարգացման ժամանակ՝ ֆայլի ամենասկզբում
ini_set('display_errors', 1);
ini_set('display_startup_errors', 1);
error_reporting(E_ALL);
Իրական սերվերում՝ ՀԱԿԱՌԱԿԸ

display_errors-ը հրապարակված կայքում պիտի լինի անջատված։

Սխալի տեքստը ցույց է տալիս ֆայլերի ուղիները, բազայի կառուցվածքը, երբեմն՝ գաղտնաբառերը։ Դա հարձակվողի համար նվեր է։

Կանոն՝ զարգացման ժամանակ՝ ամեն սխալ էկրանին։ Հրապարակելուց հետո՝ ամեն սխալ լոգ-ֆայլում։

var_dump — PHP-ի console.log-ը
<?php
$name = "Անի";
$age = 25;
$isActive = true;
$items = ["նոութբուք", "մկնիկ"];

var_dump($name);      // string(8) "Անի"  ← ցույց է տալիս ՏԻՊԸ ⭐
var_dump($age);       // int(25)
var_dump($isActive);  // bool(true)
var_dump($items);     // array(2) { ... }

// Ավելի ընթեռնելի զանգվածների համար
print_r($items);

// Ընթեռնելի ձևաչափմամբ
echo "<pre>";
print_r($items);
echo "</pre>";

// Երբ պետք է կանգնեցնել կատարումը այդ տեղում
var_dump($items);
die();   // կամ exit;
var_dump vs print_r

var_dump — ցույց է տալիս տիպը և երկարությունը։ Օգտագործիր, երբ չես հասկանում, ինչու համեմատությունը չի աշխատում։

print_r — ավելի կոմպակտ, հարմար է զանգվածների կառուցվածքը տեսնելու համար։

<pre>-ի մեջ փաթեթավորելը պարտադիր չէ, բայց առանց դրա ամեն ինչ մեկ տողում է։

օգտակար օգնական
<?php
function dd($data): void
{
    echo "<pre style='background:#1e252a;color:#e8eced;padding:14px;border-radius:8px'>";
    var_dump($data);
    echo "</pre>";
    die();
}

// Օգտագործում
dd($items);
Ինչո՞ւ dd

«dump and die»։ Laravel-ում այս ֆունկցիան ներկառուցված է և ամենաշատ օգտագործվողն է։ Սովորիր անունը հիմա — Դաս 18-ում այն ծանոթ կլինի։

07Դասարանական

Այսօր ձեռք ենք բերում աշխատող միջավայր և առաջին դինամիկ էջը։

  1. Ստուգիր php -v տերմինալում
  2. Ստեղծիր թղթապանակ մեկ index.php-ով և գործարկիր php -S localhost:8000
  3. Տեղադրիր Laragon (Full) → Start All
  4. Ընտրիր PHP 8.2+
  5. Ստեղծիր C:\laragon\www\technomarket\
  6. Reload → ստուգիր http://technomarket.test
  7. Տեղափոխիր այնտեղ HTML բլոկի պատրաստի նախագիծը
  8. Փոխանվանիր index.html → index.php
  9. Ստուգիր՝ ամեն ինչ դեռ աշխատո՞ւմ է
  10. Ավելացրու սխալների ցուցադրումը և dd() ֆունկցիան
Ութերորդ քայլի մասին

.html-ից .php փոխանվանելով՝ էջում ոչինչ չի փոխվում։ Դա ճիշտ է և կարևոր է տեսնել․

Ամեն վավեր HTML ֆայլ արդեն վավեր PHP ֆայլ է։ PHP-ն պարզապես դուրս է գրում այն ամենը, ինչ <?php ?>-ից դուրս է։

Հիմա կարող ես աստիճանաբար ավելացնել դինամիկա՝ առանց ամեն ինչ վերաշարադրելու։ Հաջորդ դասերին հենց դա կանենք։

առաջին դինամիկ փոփոխությունը
<!-- Footer-ում, ֆիքսված 2026-ի փոխարեն -->

<p>&copy; <?= date("Y") ?> ՏեխնոՄարկետ</p>

<!-- Հաջորդ տարի ինքն իրեն կթարմացվի։
     Փոքր բան է, բայց արդեն դինամիկ էջ է։ -->

08Տնային աշխատանք

  1. Տեղադրիր Laragon։ Ուղարկիր սքրինշոթ երկու կանաչ ցուցիչով։
  2. Գործարկիր php -S և Laragon։ Գրիր, ի՞նչ տարբերություն նկատեցիր։
  3. Տեղափոխիր ՏեխնոՄարկետը www-ի մեջ և բաց արա .test հասցեով։
  4. Փոխանվանիր index.html → index.php։ Համոզվիր, որ ամեն ինչ աշխատում է։
  5. Դարձրու footer-ի տարեթիվը դինամիկ։
  6. Ստեղծիր փոփոխականներ կայքի անվան, հեռախոսի և հասցեի համար։ Օգտագործիր դրանք էջում առնվազն 3 տեղում։
  7. Ավելացրու սխալների ցուցադրումը։ Դիտմամբ արա սխալ (մոռացիր ;) և նկարագրիր հաղորդագրությունը։
  8. Գրիր dd() ֆունկցիան և փորձարկիր այն 4 տարբեր տիպի վրա։
  9. Համեմատիր var_dump-ը և print_r-ը զանգվածի վրա։ Ո՞րն է ավելի հարմար և ե՞րբ։
  10. Բացիր էջը և սեղմիր Ctrl+U։ Գտի՞ր PHP կոդը։ Բացատրիր, ինչու։

09Հիշելու թերթիկ

ԳրառումԻնչ է անում
<?php ... ?>PHP բլոկ
<?= $x ?>Կարճ echo ⭐
$nameՓոփոխական
.Տողերի միացում
var_dump($x)Տիպ + արժեք ⭐
print_r($arr)Ընթեռնելի զանգված
die()Կանգնեցնել կատարումը
date("Y")Ընթացիկ տարին
error_reporting(E_ALL)Ցույց տալ բոլոր սխալները

Ախտորոշում

Սպիտակ էջ → միացրու error_reporting Կոդը երևում է → բացել ես file:// -ով, ոչ http:// -ով 404 → սխալ ուղի կամ ֆայլի անուն 500 → շարահյուսական սխալ, նայիր լոգերում Apache չի գործարկվում → 80 պորտը զբաղված է

Ստուգաթերթ

  • Laragon-ը գործարկվում է, երկու ցուցիչն էլ կանաչ են
  • PHP տարբերակը 8.2+ է
  • Նախագիծը հասանելի է .test հասցեով
  • Սխալները ցուցադրվում են
  • Հասկանում եմ, ինչու PHP կոդը չի երևում Ctrl+U-ով

Ինքնաստուգում

  • Կարո՞ղ եմ բացատրել client-side և server-side տարբերությունը
  • Գիտե՞մ, ինչո՞ւ php -S-ը բավարար չէ մեր դասընթացի համար
  • Հասկանո՞ւմ եմ, որ PHP-ն HTML գեներատոր է
  • Գիտե՞մ, ինչու display_errors-ը վտանգավոր է իրական սերվերում
Հաջորդ դասին

Շարահյուսություն՝ արագ անցում JavaScript-ից։ Տիպեր, ==-ի և ===-ի տարբերությունը (PHP-ում այն ավելի վտանգավոր է, քան JS-ում), տողերի հետ աշխատանք, պայմաններ և ցիկլեր։

Գաղափարները ծանոթ են — կենտրոնանալու ենք միայն տարբերությունների վրա։
