HeidiSQL, թե phpMyAdmin

HeidiSQL-ը Laragon-ի մեջ արդեն կա և կարգավորում չի պահանջում։ phpMyAdmin-ը նույն գործն անում է բրաուզերում։ Այն կարելի է ավելացնել Laragon-ի Quick add մենյուից, և հաճախ կհանդիպես այն հոսթինգներում (Դաս 22)։

SQL-ը երկու դեպքում էլ նույնն է։ Մենք գրում ենք հարցումները ձեռքով, ոչ թե սեղմում կոճակներ, որովհետև PHP-ում նույնպես ձեռքով ենք գրելու։

առաջին հրամանը — բազայի ստեղծում
CREATE DATABASE technomarket
    CHARACTER SET utf8mb4
    COLLATE utf8mb4_unicode_ci;

USE technomarket;
utf8mb4, ոչ utf8

MySQL-ում հին utf8 անունով կոդավորումը իրականում լրիվ UTF-8 չէ․ այն չի պահում էմոջիները և որոշ նիշեր։ Ճիշտը utf8mb4-ն է։

Եթե այս տողը մոռանաս, հայերենը կարող է աշխատել, բայց առաջին ապրանքը «📱» նշանով կհայտնվի որպես ???? կամ կառաջացնի սխալ։ Դա Դաս 2-ի mb_ ֆունկցիաների նույն պատմությունն է՝ բազայի մակարդակում։

SQL-ի երեք կանոն

1. Ամեն հրաման ավարտվում է ;-ով։
2. Հիմնաբառերը (SELECT, FROM) գրում ենք մեծատառ։ Պարտադիր չէ, բայց այդպես ավելի հեշտ է կարդալ, թե որն է հրամանը և որն է աղյուսակի անունը։
3. Տեքստը միշտ 'մեկ չակերտի' մեջ է։ Թվերը՝ առանց չակերտների։

03Տվյալների տիպեր

PHP-ում փոփոխականը կարող է պարունակել ցանկացած բան։ Բազայում ամեն սյունակ ունի մեկ տիպ, և բազան չի թույլ տա դրանում պահել այլ բան։ Դա Դաս 3-ի տիպերի հայտարարման նույն գաղափարն է, միայն ավելի խիստ։

ՏիպԻ՞նչ է պահումՏեխնոՄարկետում
INT UNSIGNEDԱմբողջ թիվ, ոչ բացասականid, stock
VARCHAR(200)Կարճ տեքստ, առավելագույնը 200 նիշname, slug
TEXTԵրկար տեքստdescription
DECIMAL(10,2)Ճշգրիտ թիվ ստորակետովprice ⭐
TINYINT(1)Այո/ոչ՝ 1 կամ 0is_active
DATETIMEԱմսաթիվ և ժամcreated_at
Գները երբեք FLOAT չեն

FLOAT-ը պահում է մոտավոր արժեք։ Փորձիր JS-ի կոնսոլում 0.1 + 0.2։ Արդյունքը 0.30000000000000004 է։ Բազայում FLOAT-ը նույն ձևով է աշխատում։

Մեկ ապրանքի վրա դա աննկատ է։ Հազար պատվերի վրա գումարները չեն համընկնի։ DECIMAL(10,2)-ը պահում է ճշգրիտ արժեք․ ընդհանուր 10 նիշ, որոնցից 2-ը ստորակետից հետո։

Այլընտրանք՝ գումարը պահել INT-ով, դրամով։ Հայկական դրամի դեպքում դա հաճախ ամենապարզն է (Laravel-ում այդպես կանենք Դաս 20-ում)։

04CREATE TABLE

products աղյուսակը
CREATE TABLE products (
    id          INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    name        VARCHAR(200)  NOT NULL,
    slug        VARCHAR(200)  NOT NULL UNIQUE,
    specs       VARCHAR(255)  NULL,
    description TEXT          NULL,
    price       DECIMAL(10,2) NOT NULL,
    discount    TINYINT UNSIGNED NOT NULL DEFAULT 0,
    stock       INT UNSIGNED  NOT NULL DEFAULT 0,
    image       VARCHAR(255)  NULL,
    is_active   TINYINT(1)    NOT NULL DEFAULT 1,
    created_at  DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB;
ԲառՆշանակություն
PRIMARY KEYՏողի եզակի «անձնագիրը»։ Երկու տող չեն կարող ունենալ նույն id-ն
AUTO_INCREMENTԲազան ինքն է տալիս հաջորդ համարը՝ 1, 2, 3…
NOT NULLԴատարկ թողնել չի կարելի
NULLԿարող է դատարկ լինել
DEFAULT 0Եթե արժեք չես տալիս, կլինի 0
UNIQUEԱրժեքը չի կարող կրկնվել (երկու ապրանք նույն slug-ով)
CURRENT_TIMESTAMPԸնթացիկ ամսաթիվը և ժամը ավելացնելու պահին
Կանոնները բազայում, ոչ միայն PHP-ում

NOT NULL-ը և UNIQUE-ը վալիդացիա են բազայի մակարդակում։ Դաս 6-ում ստուգեցիր դաշտերը PHP-ում։ Բայց եթե վաղը ինչ-որ մեկը մոռանա ստուգումը կամ ավելացնի տվյալ ուղիղ HeidiSQL-ով, բազան միևնույնն է չի թույլ տա դատարկ անուն կամ կրկնվող slug։

Դա պաշտպանության երկրորդ շերտն է։ Այս գաղափարը կհանդիպես Դաս 11-ում և Laravel-ում։

slug և is_active

slug-ը ապրանքի անունն է հասցեի համար՝ /product/noutbuq-pro-14։ Այն կօգտագործենք Դաս 15-ում։

NULL-ը հատուկ է

WHERE specs = NULL-ը երբեք ոչինչ չի վերադարձնի, նույնիսկ եթե երկու ապրանք specs չունեն։

NULL-ը նշանակում է «անհայտ», ոչ թե «դատարկ արժեք»։ Իսկ երկու անհայտ բան հավասար չեն։ Ճիշտ ձևը՝ WHERE specs IS NULL և IS NOT NULL։ Սա սկսնակների ամենահաճախ սխալներից է։

ORDER BY և LIMIT

տեսակավորում և քանակ
-- Էժանից թանկ
SELECT name, price FROM products ORDER BY price ASC;

-- Ամենաթանկ 3-ը
SELECT name, price FROM products ORDER BY price DESC LIMIT 3;

-- Կատալոգի 2-րդ էջը, 4 ապրանք էջում
SELECT name, price FROM products
WHERE is_active = 1
ORDER BY created_at DESC
LIMIT 4 OFFSET 4;
Հարցման մասերը միշտ այս կարգով SELECT ← ի՞նչ սյունակներ FROM ← ո՞ր աղյուսակից WHERE ← ո՞ր տողերը ORDER BY ← ինչպե՞ս դասավորել LIMIT ← քանի՞սը Կարգը խախտելը սխալ է։ WHERE-ը ORDER BY-ից հետո չի կարող լինել։

Հաշվարկվող սյունակ

Դաս 3-ի finalPrice()-ը՝ SQL-ում
SELECT
    name,
    price,
    discount,
    ROUND(price * (100 - discount) / 100) AS final_price
FROM products
WHERE is_active = 1
ORDER BY final_price;
Ֆիլտրը՝ բազայում, ձևաչափը՝ PHP-ում

Դաս 3-ում ապրանքները ֆիլտրեցինք array_filter-ով և տեսակավորեցինք usort-ով։ Բազան դա անում է ավելի արագ և վերադարձնում է միայն արդյունքը։

Ընդհանուր կանոն․ ֆիլտրում և տեսակավորում՝ բազայում, ձևաչափում՝ PHP-ում։ Օրինակ՝ գինը «450 000 ֏» ձևով ցույց տալը PHP-ի գործն է։

07UPDATE և DELETE

փոխել
-- Մեկ ապրանքի գինը
UPDATE products SET price = 370000 WHERE id = 1;

-- Մի քանի սյունակ միանգամից
UPDATE products SET discount = 10, stock = 5 WHERE slug = 'monitor-24';

-- Ջնջել
DELETE FROM products WHERE id = 12;
Մոռացված WHERE

UPDATE products SET price = 100;

Այս հրամանը սխալ չի տալիս։ Այն բոլոր ապրանքների գինը դարձնում է 100 դրամ։ DELETE FROM products;-ը ջնջում է ամբողջ աղյուսակը։ «Undo» կոճակ չկա։

Սա իրական կյանքում պատահում է նաև փորձառու մշակողների հետ։ Պաշտպանվելու սովորություն․ նախ գրիր SELECT նույն WHERE-ով, տես, թե որ տողերն են ընտրվում, և միայն հետո փոխիր SELECT-ը UPDATE-ի կամ DELETE-ի։

անվտանգ սովորություն
-- Քայլ 1. ո՞ր տողերը կփոխվեն
SELECT id, name, stock FROM products WHERE stock = 0;

-- Քայլ 2. նույն WHERE-ով
UPDATE products SET is_active = 0 WHERE stock = 0;
Թաքցնել, ոչ ջնջել

Եթե ջնջես ապրանք, որը արդեն ինչ-որ մեկը գնել է, պատվերների պատմությունում կհայտնվի «անհայտ ապրանք»։ Ուստի առցանց խանութներում ապրանքը սովորաբար չեն ջնջում, այլ թաքցնում են՝ is_active = 0։

Կայքը ցույց է տալիս միայն WHERE is_active = 1, իսկ տվյալները մնում են։ Laravel-ում այս գաղափարը կոչվում է soft delete (Դաս 20)։

08Դասարանական

  1. Բացիր HeidiSQL-ը և ստեղծիր technomarket բազան utf8mb4-ով
  2. Ստեղծիր products աղյուսակը
  3. Կատարիր seed.sql-ը և փորձիր երեք սխալը
  4. Գրիր 10 հարցումը ներքևում
  5. Կատարիր «անվտանգ սովորության» երկու քայլը
10 հարցում
-- 1. Բոլոր ապրանքների անունը և գինը
-- 2. Միայն ակտիվ ապրանքները
-- 3. 100 000 դրամից էժան ապրանքները
-- 4. Զեղչով ապրանքները
-- 5. Ապրանքները, որոնք պահեստում չկան (stock = 0)
-- 6. Անվան մեջ «Սմարթֆոն» բառը պարունակողները

-- 8. Ամենաթանկ 3 ապրանքը
-- 9. Ակտիվ ապրանքները՝ զեղչված գնով, էժանից թանկ
-- 10. Կատալոգի 3-րդ էջը՝ 4 ապրանք էջում, նորերը առաջինը
Ինչո՞ւ այսօր առանց PHP-ի

Եթե SQL-ը սովորես PHP-ի տողերի ներսում, սխալի դեպքում պարզ չի լինի՝ խնդիրը SQL-ո՞ւմ է, թե՞ PHP-ում։ HeidiSQL-ում սխալը անմիջապես երևում է հստակ հաղորդագրությամբ։

Երբ Դաս 10-ում հարցումը տեղափոխես PHP, արդեն կիմանաս, որ SQL-ը ճիշտ է։ Դա HTML բլոկի նույն սկզբունքն է՝ մեկ նոր բան միանգամից։

09Տնային աշխատանք

Մինի-նախագիծ

Այս տնայինի գլխավոր մասը՝ «Դարակը՝ MySQL-ում», Անիի գրքերի ակումբում՝ քայլ առ քայլ, starter ֆայլերով և պատրաստի օրինակով։ Ներքևի ցուցակի կետերը, որ նշված չեն որպես «մինի-նախագծում», կատարիր ՏեխնոՄարկետում։

  1. Ավարտիր դասարանականի 10 հարցումը։ Ուղարկիր SQL-ը և արդյունքների սքրինշոթները։
  2. Ավելացրու ևս 5 ապրանք քո ընտրությամբ, որոնցից մեկը՝ էմոջիով անվան մեջ։ Ստուգիր, որ այն ճիշտ է ցուցադրվում։
  3. Ցույց տուր WHERE specs = NULL-ի և WHERE specs IS NULL-ի տարբերությունը։
  4. Գրիր հարցում, որը գտնում է 50 000 – 150 000 դրամ արժեցող ակտիվ ապրանքները՝ թանկից էժան։
  5. Թաքցրու (is_active = 0) բոլոր ապրանքները, որոնք պահեստում չկան։ Նախ՝ SELECT։
  6. Հաշվարկիր զեղչված գինը և ցույց տուր միայն այն ապրանքները, որոնց զեղչված գինը 100 000-ից փոքր է։ Հուշում․ WHERE-ում final_price-ը դեռ չկա, կրկնիր բանաձևը։
  7. Խնդրիր AI-ին գրել 5 հարցում քո աղյուսակի համար, ապա կատարիր դրանք։ Բոլորը աշխատեցի՞ն։ Եթե ոչ՝ ինչու։
